# 예비 검수 dynamic_dict_r2

설계서 `dynamic_aki.json`, 데이터 설명서 있음. 에이전트의 마지막 메시지 원문.

---

설계에 문제가 있어 진행 전에 보고합니다. 모델 학습은 하지 않았고, 설계서와 데이터 파일은 고치지 않았습니다. 보고서는 `prereview_report.md`에 한국어로 썼습니다.

데이터 확인은 지시대로 Write로 스크립트를 만들어 python으로 실행했습니다. 다만 이 환경의 pandas는 dateutil이 없어 불러올 수 없어서, 표준 라이브러리로 설계 규칙대로 랜드마크 행을 다시 만들어 셌습니다. 아래 숫자는 이 재구성 기준입니다. 재구성 결과 랜드마크는 25,851행, 그중 양성은 1,536행이었습니다.

**진행 전에 결정이 필요한 문제**
1. **질문과 결과가 다릅니다.** 질문은 "AKI 예측"인데 결과(`aki_or_death_48h`)에는 원내 사망도 들어 있습니다. 양성 1,536행 중 188행(12%)은 AKI 없이 사망만으로 양성입니다. 결과를 AKI만으로 하든지, 질문을 복합 결과로 고쳐야 합니다.
2. **검증 방식이 배포 목적과 맞지 않습니다.** 목적은 2160년 이후 전향 배포인데, 분할은 무작위 가족 단위입니다. 데이터에는 시간에 따른 변화가 있습니다.
   - ICU 비율이 21%에서 27%로 늘었습니다.
   - 병동 채혈 간격이 줄었습니다.
   - 크레아티닌 측정법이 바뀌었습니다.

   따라서 시간 기준 검증이 필요합니다.
3. **설계서 안에 모순이 있습니다.** `cr_last` 항목에는 "측정법을 함께 넣는다"고 적혀 있지만, 특징 목록에 측정법이 없습니다. 학습 자료의 절반 가까이는 jaffe(+0.10 mg/dL)이고, 배포 시점 자료는 모두 enzymatic입니다.

**처리 방식을 적고 한계로 보고하면 되는 문제**
4. 창 안에 퇴원하거나 측정이 없으면 음성으로 봅니다. 창 안 퇴원이 47%의 행이고, 병동 행의 29%는 창 안에 크레아티닌 측정이 없습니다. 그래서 결과는 사실상 "입원 중 채혈로 검출된 AKI"입니다.
5. 바로 이어진 입원(같은 episode)을 따로 다뤄서 기준값과 제외 기준이 처음부터 다시 잡힙니다. 둘째 입원 727행 중 79행은 앞 입원에서 이미 AKI가 있었는데도 제외되지 않습니다.
6. `problem_ckd_active`에서 tp 시점 최신 버전을 먼저 고를지, 코드·상태 필터를 먼저 걸지 정해져 있지 않습니다. 순서에 따라 90행의 값이 달라집니다.
7. 과거 기록을 등록 번호(`patient_id`)로 볼지 사람(`person_id`)으로 볼지 정해져 있지 않습니다. `person_id` 연결은 자료 추출 때 한 번에 하므로, 실시간 배포에서는 쓸 수 없을 수 있습니다. 값이 달라지는 행은 12행입니다.
8. tp 전에 채취했지만 tp 뒤에 보고된 AKI 값을 어떻게 다룰지 정해져 있지 않습니다. 32행이 해당합니다.

특징의 시점 누설은 찾지 못했습니다. 모든 특징이 값이 알려지는 시각을 쓰고, 결과 대리변수는 특징에 없습니다. 전처리·조율·임계값·보정도 모두 학습 부분 안에서 맞춥니다.

확인 스크립트(`check1.py`, `check2.py`)는 작업 폴더가 아닌 세션 임시 폴더에 있습니다.
