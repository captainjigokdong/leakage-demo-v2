# 예비 검수 dynamic_nodict

설계서 `dynamic_aki.json`, 데이터 설명서 없음. 에이전트의 마지막 메시지 원문.

---

설계서와 데이터를 대조해 본 결과, **이 설계로는 진행하면 안 됩니다.** 진행 전에 고쳐야 할 문제가 6개 있습니다. 숫자 근거를 붙인 전체 보고서는 `prereview_report.md`에 있습니다. 모델 학습과 성능 계산은 하지 않았고, 설계서와 데이터 파일도 고치지 않았습니다.

랜드마크 수는 모든 입원(7,806건)에 입원 후 24~168시간 시점 7개를 적용해 센 값입니다(총 54,642개).

## 진행 전에 반드시 고칠 문제
1. **tp에 입원 중이어야 한다는 조건이 없습니다.** 랜드마크 25,488개(46.6%)는 tp가 이미 퇴원한 뒤이고, 모두 음성으로 처리됩니다.
2. **48시간을 다 관찰하지 못한 행의 처리가 서로 모순됩니다.** `min_followup`은 tp+48h인데 추적 실패는 음성으로 처리하게 되어 있습니다.
   - 입원 중인 랜드마크의 46.7%(13,608개)가 tp+48h 전에 퇴원합니다(귀가, 전원, 사망).
   - 6,882개는 결과 구간에 크레아티닌 측정이 아예 없습니다.
3. **사망을 결과에 넣을지가 일치하지 않습니다.** 검열 항목은 사망을 결과에 포함하라고 하지만, 결과 정의는 크레아티닌 기준만 말합니다.
4. **중복 제거 키 `admission_id` 때문에 입원당 1행만 남습니다.** 입원당 최대 7개 랜드마크를 쓴다는 설정과 충돌합니다. 키를 `(admission_id, tp)`로 바꿔야 합니다.
5. **분할 키가 같은 사람을 묶지 못합니다.** 환자번호가 2개인 사람이 105명 있고, 그중 84명은 가족 번호가 없어 환자번호 기준으로 나뉩니다. 이러면 한 사람이 학습셋과 시험셋에 같이 들어갈 수 있습니다. 교차검증 키에는 대체 키가 아예 없고, 환자의 80%는 가족 번호가 비어 있습니다. `person_id` 기준으로 묶어야 합니다.
6. **KDIGO 기준값이 tp+48h까지의 최솟값입니다.** 나중에 잰 값이 기준이 될 수 있어, 크레아티닌이 회복 중인 환자도 AKI로 판정됩니다. 각 값은 그보다 먼저 잰 값과만 비교해야 합니다.

## 결정이나 확인이 필요한 문제
- **연속 입원이 둘로 나뉘어 있습니다.** 앞 입원이 전원으로 끝나고 1시간 안에 다음 입원이 이어지는 경우가 225건입니다(A→B 107건). 뒤 입원에서는 앞 입원의 기준값, 이미 생긴 AKI, 투석 기록이 보이지 않습니다.
- **2158년 12월부터 입원 자료가 갑자기 줄어듭니다.** 월 75건 안팎에서 7~22건이 됩니다. 같은 기간 외래 검사는 정상이어서 추출 누락이 의심됩니다.
- **전향적 배포가 목적인데 무작위 분할만 합니다.** 2155년에 크레아티닌 측정법과 진단 코드 체계가 모두 바뀌었습니다. 시간 기준 검증을 추가하고, 측정법 특징(`cr_method`)을 쓸지 다시 보는 것이 좋습니다.
- **코드 필터의 일치 규칙이 없습니다.** 설계서는 `N17`, `N18`처럼 앞자리만 적었지만 데이터에는 `N17.9`, `N18.3` 같은 세부 코드만 있습니다. 완전 일치로 구현하면 0건이 됩니다.
- **"병동" 층의 기준이 둘입니다.** 검수에는 입원 첫 병동을, 평가에는 tp 시점 병동을 씁니다. 크레아티닌 측정은 ICU가 하루 약 1.53회, 병동이 약 0.73회여서 어느 쪽으로 보고하느냐가 중요합니다.

나이가 환자번호마다 하나뿐인 문제, 병원 B가 입원의 3.6%뿐인 문제 같은 경미한 항목과, 확인해 보니 문제가 없던 항목도 보고서에 정리해 두었습니다. 문제가 없던 항목에는 검사 보고 시각, 진단 코딩 시각, 문제 목록 버전 관리가 있습니다.
