# 예비 검수 fixed_dict_r2

설계서 `fixed_readmission.json`, 데이터 설명서 있음. 에이전트의 마지막 메시지 원문.

---

설계에서 누출은 찾지 못했지만, 진행 전에 정해야 할 문제가 3개 있습니다. 보고서는 `prereview_report.md`에 한국어로 저장했습니다. 모델 학습과 성능 계산은 하지 않았고, 설계서와 데이터 파일은 고치지 않았습니다.

**누출 점검 결과:** 모든 특징이 퇴원 시각(tp)에 알 수 있는 시각 열(검사 보고 시각, 활력 입력 시각, 진단 코딩 시각, 문제 목록 기록 시각)로 잘려 있습니다. 결과를 미리 드러내는 변수(예약의 `admission_id`, 퇴원 뒤 추적 외래)도 특징에서 빠져 있습니다.

**진행 전에 정해야 할 문제**
1. **분할 방식이 용도와 맞지 않습니다 (가장 중요).** 설계의 목적은 2160년 이후 실제 배치인데, 분할은 같은 기간 안의 가족 단위 무작위 분할입니다. 데이터에는 시간에 따른 변화가 있습니다.
   - ICU 비율이 0.20에서 0.29로 늘어남
   - 크레아티닌 측정법이 2155년에 바뀜
   - 진단 코드가 ICD-9에서 ICD-10으로 바뀜

   그래서 무작위로 뽑은 시험 세트의 성능은 배치 때보다 좋게 나올 수 있습니다. 시간순 분할로 평가하거나 함께 보고하기를 권합니다.
2. **`cr_last` 측정법 처리가 설계서 안에서 맞지 않습니다.** 설명에는 "측정법을 함께 넣는다"고 되어 있지만, 특징 목록에도 전처리에도 측정법 변수가 없습니다. 측정법 변수를 추가할지, 값을 보정할지, 층화 평가만 할지 정해야 합니다.
3. **사전 이력 특징의 정의가 모호합니다.**
   - `n_prior_adm`: 창 끝이 tp를 포함하면 인덱스 입원 자신이 세어집니다. 같은 에피소드의 앞 입원을 뺀다는 조건도 설명에만 있고 창 정의에는 없습니다(해당 190행).
   - 진단 이력과 문제 목록 특징이 등록 번호(`patient_id`) 기준인지 사람(`person_id`) 기준인지 적혀 있지 않습니다. 설명서상 `person_links`는 자료 추출 때 한 번에 연결되므로 tp에는 쓸 수 없습니다. 특징을 `person_id`로 모으면 배치 때 없는 정보를 쓰게 되므로, `patient_id` 기준이라고 명시해야 합니다.

**보고서에 한계로 적을 것**
- family_id가 80% 비어 있습니다. 기록되지 않은 가족도 위험을 공유하므로, 가족 단위 분할로도 일부 가족이 학습·시험 세트에 나뉘어 들어갑니다.
- 데이터 밖 병원 입원은 음성으로 셉니다.

**데이터로 확인한 것**
- 추적 완료 기준 2158-12-01은 충분합니다. 원외 사망 기록은 최대 179일 늦게 들어오므로, 실제로 필요한 기준은 2158-12-03입니다.
- 예정 입원 572건과 예약으로 이루어진 입원 572건이 정확히 일치합니다.
- 에피소드 구조와 사망 연계도 설명서와 같습니다.
- 진단 코드 필터(N18/585/I50/428)가 데이터의 코드를 모두 잡습니다.
- 코호트는 6,514행이고, 그중 양성이 942행입니다.

환경의 pandas가 `dateutil`이 없어 import되지 않아서, 확인 스크립트는 표준 라이브러리로 다시 짰습니다. 스크립트는 세션 scratchpad에 있습니다.
