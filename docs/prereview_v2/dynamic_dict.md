# 예비 검수 dynamic_dict

설계서 `dynamic_aki.json`, 데이터 설명서 있음. 에이전트의 마지막 메시지 원문.

---

설계서에 진행 전에 고쳐야 할 문제가 있어 보고서로 정리했습니다: `design_review.md`

모델 학습과 성능 계산은 하지 않았고, 설계서와 데이터 파일도 고치지 않았습니다. 셸 실행 권한이 없어 `.csv.gz` 데이터는 열어 보지 못했습니다. 아래 지적은 모두 `design.json`과 `data_dictionary.md`를 맞대어 본 결과이며, 실제 데이터로 확인하지는 않았습니다.

**진행 전에 반드시 고칠 것**
1. **tp에 입원 중이어야 한다는 조건이 없습니다.** 재원 기간 중앙값이 80~110시간인데 tp는 168시간까지 있습니다. 그래서 이미 퇴원하거나 사망한 뒤에도 예측 행이 생기고, 이 행들은 `count_as_negative`에 따라 모두 음성이 됩니다. 쉬운 음성이 많아져 성능이 부풀려집니다. 포함 조건에 `discharge_time > tp`를 넣어야 합니다.
2. **중복 제거 키가 `admission_id`입니다.** 입원 하나에 랜드마크 행이 최대 7개인데, 이 키로 중복을 제거하면 입원마다 한 행만 남습니다. 키를 `landmark_row_id`로 바꿔야 합니다.
3. **분할에서 `family_id`가 없을 때 쓰는 키가 `patient_id`입니다.** `family_id`는 약 80%가 비어 있어 대부분 이 키로 나뉩니다. 그런데 사람의 약 2%는 등록 번호가 둘이라 같은 사람이 학습과 평가 양쪽에 들어갈 수 있습니다. 분할과 튜닝 모두 `person_id`를 써야 합니다.
4. **결과 정의가 서로 맞지 않습니다.**
   - `death: composite_outcome`이면 사망도 양성인데, 결과 이름과 정의는 크레아티닌 기준만 말합니다.
   - `min_followup: tp+48h`는 48시간 추적을 요구하지만, `count_as_negative`와 `outcome_missing: not_applicable`은 측정이 없으면 음성으로 봅니다.
   - 병동은 채혈 간격이 30~72시간이라 48시간 결과 창에 크레아티닌이 아예 없는 행이 많습니다. 결과 창에 크레아티닌이 없는 행을 어떻게 처리할지 하나로 정해야 합니다.
5. **이어진 입원을 따로따로 다룹니다.** 입원의 3%는 병원·진료과 이동으로 한 에피소드가 입원 기록 두 건으로 나뉩니다. 뒤쪽 입원에서는 앞 입원 때 이미 AKI였거나 투석 중이던 환자가 제외되지 않고, 결과의 기준값에서도 앞 입원 값이 빠집니다. 범위를 `episode_id` 단위로 잡아야 합니다.

**고치는 것이 좋은 것**
- **KDIGO 판정 규칙:** "+0.3 mg/dL/48시간" 기준을 기준값 하나(최솟값)로는 구현할 수 없습니다. 어떤 값끼리 비교하는지 적어야 하고, 측정법 전환 규칙을 제외 조건에도 똑같이 적용한다고 적어야 합니다.
- **코드 필터:** 설계는 `N18`·`585`인데 데이터는 `N18.3`·`585.x`입니다. 앞부분 일치로 비교한다고 명시해야 합니다. 문제 목록은 tp 시점의 최신 버전을 고른다고 적어야 합니다.
- **이전 기록:** `person_id`는 자료 추출 때 연결되므로 배포 시점에는 쓸 수 없습니다. 특징은 `patient_id` 기준으로 계산해야 합니다.
- **기타:**
  - 처방 특징에 퇴원약이 섞이지 않게 `med_type`으로 거릅니다.
  - `age`는 첫 입원 때 나이로 고정된 값이라 재입원에서는 실제보다 적습니다.
  - 외래 크레아티닌은 측정법이 섞이고 결측이 많습니다.
  - 전처리를 교차검증 접힘마다 다시 맞추지 않습니다.
  - 하위군 이름이 `unit`과 `unit_at_tp`로 섞여 있습니다.
- **목적과 검증 방식:** 목적은 추출 뒤 전향적 배포인데, 평가는 무작위 분할 한 번뿐입니다. 데이터에는 측정법 전환, 채혈 빈도 변화, ICD 코드 체계 전환이 있습니다. 시간 분할 검증을 추가하거나 한계로 적기를 권합니다.

**문제가 없다고 본 부분**
- 결과의 대리 변수는 특징에 하나도 쓰이지 않았습니다.
- 특징은 모두 tp 전에 알려진 값만 씁니다(보고·입력·코딩 시각 기준).
- 전처리, 임계값, 보정은 학습 데이터 안에서만 정하고, 평가 데이터는 한 번만 씁니다.

데이터 파일로 확인하려면(코드 표기, 병동별 결과 창 측정 비율 등) 셸 실행 권한이 필요합니다.
