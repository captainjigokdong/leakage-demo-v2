# 깨끗한 설계서 검수 readmit_c_r2

설계서 `readmit_c.json`, 스킬 없음, 데이터 설명서 없음. 에이전트의 마지막 메시지 원문.

---

## 결론
설계를 데이터와 맞춰 본 결과 **모델링을 멈춰야 할 문제는 찾지 못했다.** 시점 누수, 결과 누수, 분할 누수가 없었다. 설계가 비워 두었거나 근거 자료가 없는 곳은 가정을 두고 모델링 입력 표까지 만들었다. 모델 학습, 전처리 적합, 성능 계산은 하지 않았고 설계서와 데이터 파일도 고치지 않았다.

## 데이터로 확인한 점
- **사망 추적이 부족한 퇴원 제외:** 병원 밖 사망은 사망 14~179일 뒤에 기록되고, 사망 연계 자료는 2159-07-01까지 반영된다. 따라서 2158-12-01 뒤 퇴원을 빼는 기준은 맞다.
- **원내 사망:** 원내 사망 퇴원 160건은 모두 사망 기록과 시각이 같다. 사망 뒤 입원이나 생존 퇴원 전 사망처럼 앞뒤가 안 맞는 기록은 없다.
- **분할 묶음:** 한 사람의 여러 등록 번호는 가족 번호가 항상 같아서 가족(없으면 사람) 묶음이 깨지지 않는다. 학습과 평가 집합에 함께 들어간 묶음도 없다.
- **퇴원 뒤에 생기는 기록:** 진단 코딩은 퇴원 1~90일 뒤에 끝나고, 검사 결과 보고 5%와 문제 목록 일부도 퇴원 뒤에 기록된다. 설계대로 퇴원 시각까지의 기록만 쓰면 이런 값은 빠진다.
- **결과를 미리 알려 줄 수 있는 자료:** 입원 예약 자료와 퇴원 뒤 추적 외래는 특징에 쓰이지 않는다.
- **크레아티닌 측정법 보정:** 데이터 설명서가 폴더에 없어 0.10 mg/dL 차이를 직접 확인할 수는 없었다. 다만 연도별 중앙값이 2155년 전후로 약 0.1 차이 나서 설명과 맞는다.

## 가정 (findings.json에 7건, 점검 불가 1건)
- **측정법 설명 끊김:** `cr_last` 항목의 측정법 설명이 "측정법 자체는 특징으로 "에서 끊겨 있다. 측정법은 특징으로 쓰지 않는 것으로 보았다. 측정법은 2155년 전후와 정확히 겹치므로 넣으면 시기를 알려 주는 변수가 된다.
- **나이:** 데이터의 나이는 95에서 잘려 있는데, 설계대로 경과 연수를 더하면 61행이 95를 넘는다. 이 값은 95로 잘랐다.
- **재원 시간:** `length_of_stay_h` 열이 데이터에 없어서 퇴원 시각에서 입원 시각을 빼 계산했다.
- **에피소드 범위:** 창 시작 "admit"은 에피소드 첫 입원의 입원 시각으로 보았다. `prior_cr_last`는 창 시작과 에피소드 범위가 비어 있어, 인덱스 입원 전에 시작한 모든 입원으로 보았다.
- **다른 병원 입원:** 다른 병원 재입원은 보이지 않아 음성으로 센다. 전원 퇴원의 결과율이 더 낮으므로 퇴원처별로 따로 보고해야 한다.
- **B 병원 표본:** 평가 집합의 B 병원은 55행, 사건 9건뿐이다. B 병원 지표는 신뢰구간과 함께만 보고해야 한다.

## 준비 결과
모델링 입력 표는 6,514행이다. 에피소드 7,504개에서 원내 사망을 빼면 7,344개, 추적이 부족한 퇴원을 빼면 6,514개가 된다. 아래 결과율은 코호트를 설명하는 값이고 모델 성능이 아니다.

| 분할 | 행 | 사건 | 결과율 |
|---|---|---|---|
| 학습 | 4,149 | 619 | 14.9% |
| 평가 | 1,799 | 260 | 14.5% |
| 사용 안 함 | 566 | 63 | 11.1% |

결측은 `hgb_min` 5.5%, `prior_cr_last` 66.6%다.

남은 단계는 설계대로 학습 집합 안에서만 진행한다. 결측 대치, 인코딩, 표준화를 학습 집합에 맞추고, 5폴드 교차검증으로 설정을 고른다. 그다음 확률 보정과 판정 기준값을 정하고, 마지막으로 평가 집합을 한 번만 쓴다.

데이터 확인 스크립트(`check1.py`~`check4.py`)는 작업용 임시 폴더에 있다.
