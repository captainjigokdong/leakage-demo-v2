# 깨끗한 설계서 검수 aki_d_r1

설계서 `aki_d.json`, 스킬 없음, 데이터 설명서 있음. 에이전트의 마지막 메시지 원문.

---

설계서에서 결과 정의에 관한 문제 두 개를 찾았습니다. 둘 다 정답(레이블) 값을 바꾸고 어느 쪽으로 정할지는 판단이 필요해서, 모델링 데이터셋은 아직 만들지 않았습니다. 모델 학습과 성능 계산은 하지 않았고, 설계서와 데이터 파일도 고치지 않았습니다. 찾은 내용 8건은 `findings.json`에 저장했습니다.

## 진행 전에 정해야 할 문제

**1. `outcome.window`: 결과 창 정의가 설계서 안에서 서로 다릅니다**
- 결과 설명과 `pending_at_tp: count_as_outcome`은 "tp에 아직 보고되지 않았고 tp+48시간까지 채취된 크레아티닌"을 셉니다. tp 전에 채취하고 tp 뒤에 보고된 값도 포함된다는 뜻입니다.
- 반면 `window.start = tp`(채취 시각 기준)를 따르면 이런 값은 빠집니다.
- 데이터에서 세어 보니, 제외 기준을 거친 25,936행 중 785행은 tp 시점에 보고를 기다리는 크레아티닌이 있었습니다. 그중 45행은 그 값이 AKI였고, 33행은 어느 정의를 쓰느냐에 따라 양성과 음성이 갈립니다.
- 결정할 것: 설명대로 미보고 값을 포함할지, `window` 정의대로 tp 뒤에 채취한 값만 볼지.

**2. 이어진 입원(에피소드)을 항목마다 다르게 다룹니다**
일부 진료 에피소드는 병원이나 진료과를 옮기면서 입원 기록이 두 건으로 나뉩니다. 이런 에피소드가 220개(입원 440건)입니다.
- tp 기준 시각, 예측 행, 결과 판정 범위, `in_hospital_at_tp`는 입원 기록 단위입니다.
- 반면 AKI·투석 제외 기준과 `cr_last`·`cr_min_adm`·`n_cr`은 에피소드 단위입니다. `cr_max_48h`·`bun_last`·혈색소·활력징후에는 단위 지정이 없습니다.
- 이 차이 때문에 생기는 일:
  - 앞 입원의 349행은 이어진 입원으로 옮기는 시점이 퇴원으로 처리되어 결과 창이 잘립니다. 이 때문에 4행은 AKI를 놓칩니다.
  - 뒤 입원의 727행은 tp를 뒤 입원의 입원 시각부터 다시 셉니다. 그중 79행은 앞 입원에서 이미 AKI가 보고된 상태인데, 제외 기준을 어느 단위로 적용하느냐에 따라 코호트에 남기도 하고 빠지기도 합니다.
  - 에피소드 단위 항목의 창 시작점 `admit`가 에피소드 첫 입원 시각인지 지금 입원 시각인지 정해져 있지 않습니다.
- 결정할 것: 예측 단위, tp 기준, 결과 범위를 에피소드와 입원 기록 중 하나로 통일하는 것. 저는 에피소드 단위를 권합니다. 앞 입원에서 뒤 입원으로 넘어가는 것은 실제 퇴원이 아니기 때문입니다.

## 가정으로 두고 진행할 사항
- **AKI 제외 기준:** 비교 규칙이 적혀 있지 않아 결과와 같은 KDIGO 규칙을 쓴다고 가정했습니다. 같은 측정법끼리만 비교하고, tp까지 보고된 값만 씁니다. 측정법이 섞인 입원은 7건입니다.
- **과거 이력의 환자 키:** 과거 CKD 진단과 문제 목록은 설계대로 등록 번호(`patient_id`)로 묶습니다. 등록 번호가 둘인 사람이 111명이지만, 두 번호를 잇는 `person_id`는 자료 추출 때 연결된 값이라 tp 시점에는 알 수 없습니다.
- **퇴원·미측정 처리:** 창 안에 살아서 퇴원하거나 크레아티닌 측정이 없으면 음성으로 둡니다. 설계가 명시한 선택이므로, 병동별 보고를 함께 낸다는 전제로 따릅니다.
- **`hgb_last` 결측 표시:** `hgb_last`에는 결측 표시 열이 없지만, `hgb_min`과 같은 창을 쓰므로 결측 여부가 항상 같습니다. `hgb_min`의 표시 열로 대신합니다.

## 데이터로 점검할 수 없는 사항
- **기록되지 않은 가족:** `family_id`가 80.4% 비어 있습니다. 설명서상 기록되지 않은 가족도 위험을 공유하므로 학습과 평가로 나뉠 수 있지만, 데이터로는 찾을 수 없습니다. 확인한 것은 한 사람의 등록 번호들이 `family_id`와 성별이 모두 같다는 점입니다.
- **추출 종료 뒤 퇴원:** 퇴원이 자료 추출 종료 뒤인 입원은 처음부터 데이터에 없어서, 그로 인한 선택 편향의 크기를 알 수 없습니다.

## 문제가 없었던 사항
- 검사, 활력징후, 처방, 진단 특징은 모두 보고·입력 시각 기준으로 tp까지만 씁니다.
- AKI 대리지표(신장 오더, 투석, 이뇨제, N17)는 특징에 들어 있지 않습니다.
- 측정법 전환 시각은 데이터와 정확히 맞습니다(2155-01-01).
- 전처리, 조율, 임계값, 보정은 모두 학습 부분 안에서만 맞춥니다.

위 두 문제의 방향을 정해 주시면 그 결정과 가정을 반영해 예측 행, 특징, 결과, 가족 단위 분할을 만들겠습니다. 확인에 쓴 스크립트는 스크래치패드의 `check1.py`, `check2.py`입니다.
