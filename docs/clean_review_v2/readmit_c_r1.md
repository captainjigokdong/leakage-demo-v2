# 깨끗한 설계서 검수 readmit_c_r1

설계서 `readmit_c.json`, 스킬 없음, 데이터 설명서 있음. 에이전트의 마지막 메시지 원문.

---

설계대로 모델링용 표를 만들었습니다. 정보 누출(예측 시점에 알 수 없는 정보가 특징에 들어가는 문제)은 찾지 못했습니다. 다만 크레아티닌 측정법 문제가 하나 있어 결정이 필요합니다. 설계서와 데이터 파일은 고치지 않았고, 모델 학습과 성능 계산은 하지 않았습니다.

## 결정이 필요한 문제: 크레아티닌 측정법 혼합
- **차이:** 학습 부분의 크레아티닌은 77%(16,259건 중 12,492건)가 jaffe 측정값입니다. 평가 부분과 실제 사용 시점에는 enzymatic만 있습니다. jaffe 값은 약 0.10 mg/dL 높고, 중앙값도 1.11 대 0.99입니다.
- **영향:** 모델이 jaffe 기준으로 크레아티닌 분기점을 배웁니다. 그러면 실제 사용 때 신장 관련 위험이 낮게 추정되고 보정도 어긋날 수 있습니다.
- **평가 불가:** 설계서는 측정법별 평가를 계획했지만, 평가 부분에 jaffe 값이 하나도 없어서 할 수 없습니다.
- **빠진 특징:** `prior_cr_last`는 설계서의 측정법 설명에서 빠져 있습니다. 실제 사용 때에도 2155년 이전 입원의 jaffe 값이 들어올 수 있습니다.
- **권고:** 값을 집계하기 전에 jaffe 값에서 0.10을 빼는 것입니다. 적용할지 알려 주시면 반영하겠습니다. 지금 만든 표에는 보정을 적용하지 않았습니다.

## 설계서가 모호해 제가 정한 가정
- **제외 순서:** 에피소드의 마지막 입원을 먼저 고른 뒤 제외 기준을 적용했습니다. 순서가 반대이면 2개 에피소드에서 바로 이어진 입원이 재입원으로 잘못 세어집니다.
- **퇴원약 범위:** `n_discharge_meds`와 `dc_diuretic`은 설계서대로 에피소드 전체에서 셌습니다. 그래서 두 입원짜리 에피소드에서는 병원·진료과를 옮길 때 낸 앞 입원의 퇴원약도 들어갑니다. 이런 앞 입원의 56%에 퇴원약이 있습니다.
- **입원 단위 특징:** 범위가 지정되지 않은 특징(`unit`, `los_h`, `cr_last`, `hgb_min`, `sbp_last`)은 에피소드의 마지막 입원 기록만 썼습니다.
- **나이 상한:** 데이터의 나이가 95에서 잘려 있어 142행은 나이가 낮게 계산될 수 있습니다.
- **폴드 수:** 교차검증 폴드 수가 설계서에 없어 5로 정했습니다.
- **B 병원 표본:** 평가 부분의 B 병원은 55행뿐이라 하위군 추정이 불안정합니다.

## 데이터로 확인할 수 없는 것
- **가족 묶음:** family_id가 80% 비어 있습니다. 기록되지 않은 가족은 학습·평가에 함께 들어갈 수 있습니다.
- **다른 병원 입원:** A·B 밖의 병원 입원은 데이터에 없어 음성으로 처리됩니다.

## 확인했고 문제없는 부분
- 이전 이력 특징을 등록 번호(patient_id) 기준으로 만든 것은 맞습니다. 사람 단위 연결은 자료 추출 때 만들어지므로 실제 사용 시점에는 쓸 수 없습니다.
- 퇴원 뒤 추적이 불완전한 퇴원을 빼는 기준일(2158-12-01)은 실제 데이터의 사망 기록 지연(최대 179일)으로 계산해도 충분합니다.
- 진단·검사·활력징후·문제 목록은 모두 퇴원 시각까지 알려진 값만 씁니다.
- 결과를 미리 드러내는 예약 테이블과 추적 외래는 특징으로 쓰지 않았습니다.
