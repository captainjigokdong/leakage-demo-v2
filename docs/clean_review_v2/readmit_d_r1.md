# 깨끗한 설계서 검수 readmit_d_r1

설계서 `readmit_d.json`, 스킬 없음, 데이터 설명서 있음. 에이전트의 마지막 메시지 원문.

---

모델링에 쓸 표는 다 만들었습니다. 설계를 점검했지만 작업을 멈춰야 할 문제(정보 누출, 결과 정의 오류)는 찾지 못했습니다. 다만 아래 다섯 가지는 보고드립니다. 모델 학습과 성능 계산은 하지 않았고, 설계서와 데이터 파일은 그대로 두었습니다.

**보고할 항목** (`findings.json`에 저장)

1. **문제: 특징마다 보는 범위가 다릅니다.** 코호트는 에피소드의 마지막 입원 하나만 씁니다. 그런데 icu_any, 퇴원약 수, 투석 오더는 에피소드 전체를 보고, los_h, unit, 검사·활력 특징은 마지막 입원만 봅니다.
   - 입원 두 건으로 나뉜 에피소드는 190행입니다.
   - 이 행들의 los_h는 중앙값이 85시간인데, 에피소드 전체로 재면 187시간입니다.
   - 설계서에 적힌 대로 만들었습니다. 에피소드 전체를 기준으로 하려던 것이라면 설계서를 고쳐야 합니다.
2. **가정: 이력 특징은 patient_id로 모았습니다.** 결과는 person_id(같은 사람의 모든 등록 번호)로 정하지만, 이력 특징은 patient_id 기준입니다. person_id 연결은 자료를 추출할 때 이루어져 퇴원 시점(tp)에는 알 수 없으므로, 의도한 설계로 보았습니다.
   - 등록 번호가 둘인 사람의 행은 242개입니다.
   - 이 때문에 n_prior_adm이 실제보다 적게 세어진 행이 78개입니다.
3. **점검 불가: 평가 성능이 실제보다 좋게 나올 수 있습니다.** family_id가 인덱스 행의 80.8%에서 비어 있습니다. 기록되지 않은 가족은 학습과 평가에 나뉘어 들어갈 수 있는데, 데이터로는 찾아낼 수 없습니다.
4. **점검 불가: A·B 밖의 병원 재입원은 보이지 않습니다.** 이런 재입원은 음성으로 셉니다. 결과율은 전원 퇴원 12.5%, 자택 퇴원 14.7%입니다. 전원 퇴원이 낮은 것이 재입원을 놓친 탓인지는 데이터로 가릴 수 없습니다.
5. **가정: 결측 표시 열 목록.** k_last가 목록에서 빠져 있지만 결측이 0%라 영향은 없습니다. cr_last와 sbp_last도 결측이 0%라서, 이 둘의 표시 열은 값이 모두 0입니다.

추적 제외 기준(2158-12-01 뒤 퇴원 제외)은 데이터의 사망 연계 일정과 맞았습니다. 예정 입원 제외, 진단 코드 앞부분 일치, 특징 값이 tp 이전에 알려졌는지도 데이터로 확인했고 문제가 없었습니다.
