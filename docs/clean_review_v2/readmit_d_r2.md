# 깨끗한 설계서 검수 readmit_d_r2

설계서 `readmit_d.json`, 스킬 없음, 데이터 설명서 없음. 에이전트의 마지막 메시지 원문.

---

## 요약

설계를 그대로 진행하기 어려운 결정적 문제는 없습니다. 설계서 한 곳의 문장이 끊겨 있었고, 근거 문서가 없어 확인하지 못한 항목과 해석이 필요한 가정이 몇 개 있습니다. 이를 반영해 모델링 입력 표까지 만들었습니다. 모델 학습과 성능 계산은 하지 않았고, 설계서와 데이터 파일도 고치지 않았습니다.

## 설계 문제와 가정 (`findings.json`, 10건)

**문제 (1건)**
- **`cr_last.assessment.method`**: 문장이 "측정법 자체는 특징으로 "에서 끊겨, 측정법을 특징으로 쓰는지 알 수 없습니다. 데이터에서는 측정법과 채취일이 완전히 겹칩니다(2155-01-01 전은 jaffe, 뒤는 enzymatic). 측정법은 특징으로 쓰지 않는다고 가정했습니다. 의도를 확인해 주세요.

**점검 불가 (1건)**
- **데이터 설명서**: 설계서가 근거로 드는 데이터 설명서가 작업 폴더에 없습니다. 그래서 jaffe +0.10 mg/dL 보정, 나이 95 상한, `length_of_stay_h` 파생 열의 근거를 확인하지 못했습니다.
  - 데이터로 간접 확인만 했습니다. A 병원은 2154년과 2155년 크레아티닌 차이가 0.09~0.11로 0.10과 맞습니다.
  - B 병원은 표본이 적어 확인할 수 없습니다.

**가정 (8건, 주요 항목)**
- **전원 퇴원 환자의 결과**: 다른 병원으로 전원된 퇴원(751건)은 이후 입원이 보이지 않는데 음성으로 셉니다. 결과율은 전원 12.5%, 자택 14.7%입니다. `discharge_status`가 예측 변수이기도 해서, 모형이 실제 위험 대신 결과 확인 차이를 배울 수 있습니다.
- **나이**: 95에서 잘린 환자가 103명입니다. 이들은 나이가 실제보다 작게 잡히고, 계산한 나이가 95를 넘을 수 있습니다.
- **재원 시간**: `admissions`에 `length_of_stay_h` 열이 없어 퇴원 시각과 입원 시각의 차이로 계산했습니다. 두 입원 기록으로 나뉜 에피소드(220개)는 앞 입원 시간이 빠집니다.
- **과거력의 시작점**: 자료가 2150년부터라, 2150년 퇴원 597건은 과거력이 짧게 잡힙니다.
- **해석한 항목**
  - 에피소드 특징의 시작 시각(`admit`)은 에피소드의 첫 입원 시각으로 봤습니다.
  - `unit`은 인덱스 입원 기록의 병동입니다.
  - 결과는 person_id 기준으로 퇴원 직후부터 30일 안까지 봤습니다.
- **B 병원 표본**: test에 B 병원이 74건(사건 11건)뿐이라 하위 집단 추정치가 매우 불안정합니다.

**확인해 보니 설계와 데이터가 맞는 부분**
- **추적 기간 제외 날짜(2158-12-01)**: 원외 사망은 사망 14.3~179.7일 뒤 기록됩니다. 이 기준이면 30일 안 사망이 모두 반영됩니다.
- **tp 뒤에 생기는 기록**: 검사 결과, 활력징후 입력, 진단 코딩, 문제 목록 수정이 퇴원 뒤에 생기는 경우가 있습니다. 설계의 시간 열과 창이 모두 tp에서 막습니다.
- **문제 목록**: 같은 항목 안에서 진단 코드가 바뀌는 경우가 578건 있어, 설계의 버전 처리 방식이 필요합니다.
- **결과 대리 지표**: 예약 입원 기록과 추적 외래는 특징으로 쓰이지 않습니다.
- **분할**: 같은 사람이 train과 test에 나뉘어 들어간 경우는 0건입니다.

## 준비한 결과물
- **입력 표** (`prepared/model_table.csv.gz`)
  - 에피소드 7,504개에서 제외 기준을 적용해 **6,514행**이 남았습니다. 재원 중 사망 160건, 추적 기간 부족 830건이 빠졌습니다.
  - 결과율 14.5%입니다(재입원 13.9%, 사망 0.9%).
  - 특징 18개와 결측 표시 열이 들어 있습니다. 결측은 `hgb_min`만 5.5%입니다.
  - 분할은 가족(없으면 사람) 단위로 묶었습니다. 3,924개 묶음 중 1,177개가 test로, train 4,553행과 test 1,961행입니다.
- **아직 적용하지 않은 전처리**: 중앙값 대치, 원-핫 인코딩, 표준화는 학습 데이터에 맞춰야 하므로 학습 단계에서 적용해야 합니다.
- **스크립트**: 점검용은 `checks/check1.py`~`check3.py`, 표 생성은 `checks/prepare.py`입니다.
