# 깨끗한 설계서 검수 aki_a_r2

설계서 `aki_a.json`, 스킬 없음, 데이터 설명서 없음. 에이전트의 마지막 메시지 원문.

---

설계서를 검토하면서 데이터로 랜드마크 코호트와 결과 라벨을 다시 만들어 봤습니다. 설계에 **고쳐야 할 문제가 2건** 있어서, 특징 행렬을 만드는 단계는 진행하지 않고 여기서 멈췄습니다. 모델 학습과 성능 계산은 하지 않았고, 설계서와 데이터 파일도 고치지 않았습니다. 확인용 스크립트는 scratchpad에 있습니다.

## 재구성한 코호트 (참고용)
- **재원 중인 랜드마크 행:** 28,761행입니다.
- **제외 후 남은 행:** 25,786행(7,647개 입원)입니다. 제외 기준별로 이미 AKI 2,832행, 투석 오더 687행, 추출 종료 직전 입원 60행이 빠졌습니다.
- **결과 양성률:** 6.1%입니다(AKI 1,376행, 원내 사망 188행). tp 전에 채혈했지만 tp에 아직 보고되지 않은 값으로 양성이 된 행은 32행입니다.
- **설계서 서술과 맞는 점:**
  - jaffe 값을 0.10 내리면 음성에서 양성으로 바뀌는 행은 14행으로, 설계서와 같습니다.
  - 결과 창 끝이 자료 추출 종료 뒤인 행은 없습니다.
- **시간 분할:**
  - 학습은 A 병원 16,314행, B 병원 556행입니다.
  - 평가는 A 병원 6,491행(양성 377), B 병원 282행(양성 24)입니다.
  - 학습 행의 결과 창이 경계 시각을 넘는 경우는 없습니다.

## 문제 (진행 전에 결정이 필요합니다)
1. **`preprocessing.cr_method_align`에 `n_cr`(측정 횟수)이 들어 있습니다.** 이대로면 개수에서 0.10을 빼게 됩니다.
   - 이 단계의 대상 열은 집계된 특징인데, 설명은 "집계 전 값 단위로 적용"이라 서로 맞지 않습니다.
   - 제안: `n_cr`을 빼고, 보정은 집계 전 크레아티닌 값에 적용합니다.
2. **두 입원 기록이 이어진 에피소드(220개) 처리가 일관되지 않습니다.** 모두 첫 입원이 transfer로 끝나고 1시간 안에 다음 입원이 시작되며, 44%는 병원이 바뀝니다.
   - 둘째 입원에서 랜드마크 725행이 생깁니다. 이 중 314행은 에피소드 시작 뒤 7일을 넘어, 질문의 "입원 24시간~7일" 범위를 벗어납니다.
   - 둘째 입원에서는 결과와 제외 판정의 기준 크레아티닌이 전원 시점에 다시 잡힙니다. 그런데 특징은 에피소드 전체를 봅니다.
   - 결과 창 안에 전원된 행은 이어진 입원에서 생긴 AKI 6건이 음성으로 표시됩니다.
   - `aki_known_by_tp`는 범위가 "입원"이면서 동시에 "에피소드"로 적혀 있어, 기준값을 어디까지 볼지 모호합니다.
   - 제안: 에피소드를 하나의 입원으로 보고 tp, 결과, 제외 판정을 맞출지 정해 주세요.

## 가정과 점검 불가
- **`cr_last` 평가 설명이 문장 중간에서 끊겨 있습니다.** "측정법은 특징으로 쓰지 않는다"는 뜻으로 보고 진행합니다.
- **jaffe와 enzymatic의 0.10 mg/dL 차이:** 근거로 든 데이터 설명서가 폴더에 없어 원문은 확인하지 못했습니다.
  - 측정법은 2155-01-01 채취분부터 정확히 바뀝니다.
  - 같은 외래 환자 43명의 전환 전후 차이는 평균 0.109로, 0.10과 대체로 맞습니다. 그래서 0.10을 그대로 씁니다.
- **나이 정의(첫 입원 때 나이, 95세 절단):** 설명서가 없어 확인하지 못했습니다. 첫 입원이 2150년 전이라 데이터에 없으면 인덱스 나이 계산이 틀어지는데, 이 경우도 확인할 수 없습니다. 18세 미만은 없어서 성인 기준에는 영향이 없습니다.
- **`landmark_row_id` 열이 데이터에 없습니다.** 입원 번호와 tp 오프셋(24~168시간)으로 만든다고 가정했습니다.

## 설계서가 이미 다루고 있는 점
- 병동에서는 결과 창 안에 크레아티닌 측정이 없는 행이 29%(ICU 7%)이고, 창 안에 퇴원하는 비율이 51%(ICU 33%)입니다.
- 병동 측정 빈도는 0.76회에서 0.90회로 해마다 늘어, 시간 분할에서 평가 기간 쪽 양성이 더 잘 잡힐 수 있습니다.
- 설계서에 병동별, 병동 × 연도별 보고가 계획되어 있어 문제 목록에는 넣지 않았습니다.

위 6건(문제 2, 가정 3, 점검 불가 1)은 `findings.json`에 저장했습니다. 문제 1과 2의 처리 방법을 정해 주시면 특징 행렬과 분할 준비를 이어서 하겠습니다.
