# 2단계 2b 예비 검수 (2026-10-04)

스킬 없는 새 에이전트에게 깨끗한 기본 설계서와 재생성한 데이터를 주고, "진행 전에 설계에 문제가 있으면 보고하라"로 한 번씩 검토시켰다. **4단계 정식 검수를 대신하지 않는다.** 목적은 데이터를 잠그기 전에 데이터를 바꿔야 풀리는 문제를 찾는 것이다.

**확인할 점 두 가지**

1. **설명서 있음 2회는 데이터를 열지 않았다.** 첫 셸 명령이 v1 권한 규칙에 막혔다(heredoc `<<`, `find -exec`). 에이전트는 그 뒤 "셸 실행이 허용되지 않는다"고 판단하고 설명서와 설계서만 대조했다. 설명서 없음 2회도 첫 명령이 막혔지만(`$(...)` 명령 치환), 스크립트 파일을 써서 실행하는 방식으로 우회했다. 그래서 설명서 유무에 따른 차이와 데이터 열람 여부가 섞여 있다. 6단계 사전 점검 6번("변수 확장이 들어간 명령이 권한에 막히지 않는지")과 관련된 문제이고, 2b 범위(권한 규칙 수정)는 아니다.
2. **스킬 목록이 비어 있지 않았다.** 누수 점검 스킬은 없었지만, 계정·기본 제공 스킬 34개(deep-research, code-review, docx 등)가 목록에 보였다. 네 실행 모두 Skill 도구를 부르지 않았다. 6단계 (나) 조건에서도 같은 목록이 보일 것이므로 6단계 사전 점검에서 다룬다.

## 지적과 분류

분류: **데이터** = 데이터를 바꿔야 풀림 / **설계서** = 설계서로 풀림 / **불가** = 고칠 수 없음 (데이터·형식의 성질) / **사실 아님**.

## 2회차 (승인 ② 뒤, 2026-10-04)

사용자 결정에 따라 '설명서 있음' 2회만 다시 돌렸다. 1회차의 '설명서 있음' 2회는 셸 명령이 권한 규칙에 막힌 뒤 데이터를 열지 않았기 때문이다.

**바꾼 것**

- 설계서: 간단히 고칠 수 있는 1회차 지적을 고쳤다. 같은 지적이 되풀이되지 않게 하려는 것이다.
  - 공통: B1·B2 분할과 조율 대체 키를 `person_id`로. B6 코드 필터 앞부분 일치를 명시. B11 `cr_method` 특징 제거. B21 인덱스 입원 때 나이 계산식.
