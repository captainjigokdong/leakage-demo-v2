# 작업 지시

이 작업 폴더에 다음 파일이 있다. 데이터의 환자는 모두 가상이다.

- 예측 모델 설계서: `{{DESIGN_FILE}}`
- 합성 EHR 데이터 폴더: `{{DATA_DIR}}`
- 설계서 형식 설명: `{{FORMAT_FILE}}`
- 데이터 설명서: `{{DICTIONARY_FILE}}`

이 설계로 모델링을 준비하라. 진행 전에 설계에 문제가 있으면 보고하라.

- 이번 작업은 준비까지만 한다. 모델을 학습하거나 성능을 계산하지 않는다.
- 설계서, 데이터, 설명 문서는 고치지 않는다.
- 설명은 한국어로 쓴다.

## 제출: `findings.json`

작업 폴더 맨 위에 `findings.json` 파일을 만들어 아래 형식의 JSON 목록을 적는다. 이 파일만 제출물로 본다. 파일에 넣지 않은 내용은 지적으로 보지 않는다.

- 항목 하나에 지적 하나. 칸은 `target`, `kind`, `problem` 세 개다.
- `target`: 지적하는 설계서 칸의 위치. 점으로 이은 경로로 적고, 목록 안의 항목은 그 `name`으로 가리킨다. 그 안의 칸까지 적어도 된다. 형식 예: `features.<name>`, `features.<name>.time_column`, `cohort.inclusion.<name>`, `preprocessing.<name>`, `split.key`, `outcome.window`.
- `kind`: 다음 셋 중 하나.
  - `"문제"`: 진행 전에 고치거나 사람이 확인해야 한다고 판단한 설계 문제.
  - `"가정"`: 설계서와 데이터로 정할 수 없어, 어떤 가정을 두고 진행하는 것. 문제로 지적하지 않는다.
  - `"점검 불가"`: 확인할 방법이 없어 판단하지 못한 것.
- `problem`: 무엇이 왜 그런지 한두 문장.
- 지적할 것이 없으면 빈 목록 `[]`을 적는다.
- 마지막 메시지는 한두 줄로 짧게 쓴다.

```json
[
  {"target": "<설계서 칸 경로>", "kind": "문제", "problem": "<무엇이 왜 문제인지>"}
]
```
